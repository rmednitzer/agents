# skills/

Reusable skill definitions following the Anthropic skill convention. Each skill is a directory with a `SKILL.md` at the root, optional `references/` for static knowledge, and optional `scripts/` and `assets/` for bundled code and data.

The skill description in YAML frontmatter must be specific enough that a router selects it precisely. Generic descriptions degrade routing quality.

`SkillRegistry` indexes by name and lane and supports versioning (`name@version`, latest-wins, rollback by re-add; `from_directory` takes an `allow_contract` passthrough). Seven router dispatchers: keyword, LLM, lane, routing-chain, skill-based, `MultiDispatcher` (vote/average/weighted ensemble), `EmbeddingDispatcher` (pluggable `EmbeddingProvider`; `HashingEmbeddingProvider` is a deterministic, dependency-free one). `InstrumentedDispatcher` wraps any of them with latency / fallback-rate / `DispatchObserved` telemetry, and `default_dispatcher` composes the recommended instrumented cheap-first chain in one call. A skill may ship `contract.py`; `Skill.contract()` loads it and `harness.compose_contracts` composes it with the workload contract (and `run_under_contract(skill_contracts=...)` does this on the default path). The `skills.execution.SkillContractExecutor` Protocol (`BL-133`, ADR 0016) chooses how the contract loads: `InProcessSkillContractExecutor` (default, backward-compatible) imports in the parent interpreter; `SubprocessSkillContractExecutor` (opt-in) loads and evaluates every predicate in a long-lived Python subprocess with `resource.setrlimit` caps on POSIX. The parent-child IPC is length-prefixed (4-byte big-endian, 64 MiB frame cap per `BL-216`) with pickled parent->child and JSON child->parent framing; the parent structurally validates every metadata item from the child (`BL-217`) so a malformed contract surfaces as a documented `SkillContractExecutorError`. Install bundles via `SkillSource` (`LocalSkillSource`, `GitHubSkillSource`, `MarketplaceSkillSource`): all reject path-traversing names and archive members; `LocalSkillSource` copies regular files only and refuses a symlink in the subtree; the network sources share one hardened bounded download/extract path (download / member / size caps, non-file-member rejection) and take an optional `sha256` plus a `SignatureVerifier` hook; `install_skill` does not execute a bundled `contract.py` unless `allow_contract=True`. `parse_skill_md` and `_read_body_only` translate `UnicodeDecodeError` to the documented `SkillLoadError` (`BL-215`). See [ADR 0006](../docs/adr/0006-skills-and-dispatcher.md), [ADR 0007](../docs/adr/0007-l2-implementation-wave.md), [ADR 0008](../docs/adr/0008-l3-security-hardening-and-roadmap.md), [ADR 0010](../docs/adr/0010-l3-default-path-wiring-and-audit-wave.md), [ADR 0016](../docs/adr/0016-skill-execution-isolation.md), and [ADR 0017](../docs/adr/0017-seventh-code-audit.md).
