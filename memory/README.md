# memory/

Memory backends, schemas, retrieval. Each backend exposes typed read/write per namespace with documented retention, isolation, and lineage guarantees.

Adapters: `InMemoryStore` (reference), `SQLiteStore` (stdlib, durable), `RedisStore`, `S3Store`, `DynamoDBStore` (lazy optional drivers behind the `redis`/`aws` extras; the package imports without them). Extension Protocols sit beside the core `MemoryStore`: `BatchMemoryStore`, `ScannableStore`, `ContentAddressableStore`, `CASMemoryStore`, `SweepableStore` (+ `TTLSweeper`), `BoundedSweepableStore` (`SweepableStore` plus `evict_to_capacity` for an opt-in size cap beyond age-only sweep; `TTLSweeper(max_keys=...)` drives the capacity pass after age-only sweep each interval, `BL-212` / `BL-213` / `BL-214` / `BL-224` / `BL-225`; `InMemoryStore`, `SQLiteStore`, and the opt-in `BoundedRedisStore` / `BoundedDynamoDBStore` / `BoundedS3Store` subclasses implement it, with five different eviction orderings: SQLite by rowid (overwrite shifts to newest), Redis by a per-namespace sorted-set index at `__evict_index::<namespace>` scored from a server-side INCR counter at `__evict_counter::<namespace>` (overwrite shifts to newest; both keys live outside the namespace prefix), DynamoDB by a per-item `seq` Number attribute stamped from a per-namespace atomic counter at `pk = "__evict_counter::<namespace>"` (overwrite shifts to newest; counter row lives outside the namespace data prefix), S3 by a per-object `insertion-order` user-metadata attribute stamped at write time from `time.time_ns()` (overwrite shifts to newest; no auxiliary index needed since each object carries its own ordering attribute, single-writer monotonic; multi-writer with clock skew can reorder per the existing S3 eventual-consistency contract), and InMemory by Python dict insertion order (overwrite keeps original position); the long-horizon compaction / summarisation / tiering half closed as `BL-234` / `BL-235`, see below), `VersionedMemoryStore` (MVCC content-hash version tokens, `BL-124` / `BL-180`; InMemory/SQLite/Redis/DynamoDB implement it), `TransactionalMemoryStore` (atomic multi-key version-gated transactions, `BL-180`; InMemory/SQLite/Redis/DynamoDB implement it, with `TxnWrite` / `TxnDelete` per-op dataclasses), and `SemanticMemoryStore` (vector write + similarity query, `BL-131`; `InMemorySemanticStore` reuses an injected `Embedder`, e.g. the BL-110 `HashingEmbeddingProvider`). Decorators: `EncryptedStore` (AES-256-GCM, `crypto` extra) with `StaticKeyProvider` / `EnvKeyProvider` / `FileKeyProvider` and the `VersionedKeyProvider` Protocol + `RotatingKeyProvider` reference for rotation (`BL-111`), and `ACLStore` with `RoleACL` (role/prefix) and `AttributeACL` (attribute-based, `BL-122`); `wrap_encrypted` / `wrap_acl` forward the wrapped backend's extension Protocols. Drivers and compositions over the Protocols (no new store Protocol, no adapter changes): `MemoryCompactor` + the `Summarizer` Protocol + the deterministic `TruncatingSummarizer` reference (`memory.compaction`, `BL-234`: fold N source entries into one summary entry, version-gated atomic on a `VersionedMemoryStore` + `TransactionalMemoryStore` backend, explicit `atomic=False` best-effort opt-in elsewhere), and `TieredMemoryStore` (`memory.tiering`, `BL-235`: hot/cold two-tier composition behind the plain `MemoryStore` surface with CAS-guarded promotion, hot-first writes + cold invalidation, cold-first deletes, version-gated `demote`, and BL-212-ranked `demote_to_capacity`). Optional audit events via `MemoryAudit` (`sink` + `base_event_fields`), including a `harness` `AccessDenied` event on an `ACLStore` denial. External adapters offload blocking I/O to threads so they do not stall an asyncio loop. See [ADR 0007](../docs/adr/0007-l2-implementation-wave.md), [ADR 0010](../docs/adr/0010-l3-default-path-wiring-and-audit-wave.md), [ADR 0011](../docs/adr/0011-third-audit-and-l3-capability-wave.md), [ADR 0014](../docs/adr/0014-versioned-and-transactional-on-durable-adapters.md), and [ADR 0024](../docs/adr/0024-compaction-summarisation-and-tiering.md).

Cross-namespace access is a contract violation. Tests must cover isolation explicitly.

Documented deviations and decorator scope:

- TTL precision: `InMemoryStore` / `SQLiteStore` / `S3Store` / `DynamoDBStore` keep float seconds (`DynamoDBStore` since `BL-157`), `RedisStore` uses milliseconds. The adapter-level lazy expiry, reads, scans, sweeps, and CAS all honour a sub-second TTL. DynamoDB's *native* server-side TTL sweep still reads only the integer part of `exp` and is best-effort/lagging by design (`LIMITATIONS.md` L13).
- Expiry boundary (`BL-195`, runbook 7.4 candidate 1): every Python-side liveness check across `InMemoryStore` / `SQLiteStore` / `S3Store` / `DynamoDBStore` calls `memory._expiry.is_live` / `is_expired`. The boundary is inclusive at the instant `now == expires_at` (an entry that `read` still returns is still in `list_keys` / `scan` / CAS-modifiable / not yet swept). The SQL counterpart (`expires_at < :now` for the expired half) and the DynamoDB DSL counterpart (`attribute_not_exists(exp) OR exp >= :now` for the live half) are documented in `memory/_expiry.py` as the same invariant; the prior pointwise fixes (`BL-157` / `BL-168` / `BL-177` / `BL-188` / the BL-180 DynamoDB conditions) are now expressions of one helper.
- S3 is eventually consistent: a read just after a write or delete may see the prior state.
- Decorator scope: the bare `EncryptedStore(...)` / `ACLStore(...)` constructors expose only the core `MemoryStore` surface (L1/L2 compat). Use `wrap_encrypted` / `wrap_acl` (`BL-156`) to layer a capability-rich backend: they compose a decorator forwarding exactly the extension Protocols the inner store satisfies, so `isinstance` stays truthful. `wrap_encrypted` deliberately does NOT forward `CASMemoryStore` even over a CAS backend: AES-GCM's per-write random nonce makes a ciphertext-equality compare-and-set unrepresentable, so encryption over CAS drops CAS by design rather than faking it (`LIMITATIONS.md` L12). Both decorators validate keys before any keyed operation, per the Protocol (the inner store also validates; for `EncryptedStore` the early check also prevents an AAD cross-key collision).
- Versioned + transactional + semantic scope (`BL-124`, `BL-180`, `BL-131`): the `VersionedMemoryStore` token is the SHA-256 of the *stored* bytes, so (like CAS) it is not forwarded through `EncryptedStore` (a per-write random GCM nonce makes the ciphertext token unstable); the same reasoning excludes `TransactionalMemoryStore` from `wrap_encrypted` forwarding. `BL-180` (ADR 0014) closes the BL-124 remainder by adding `VersionedMemoryStore` to `RedisStore` (WATCH/MULTI/EXEC) and `DynamoDBStore` (a server-stored `ver` content-hash attribute used in the conditional expression), and adds `TransactionalMemoryStore` with `transact(*, writes, deletes)` on every backend whose native primitives support multi-key atomicity (InMemory's lock, SQLite's `BEGIN IMMEDIATE`, Redis `WATCH(all keys)` / `MULTI`, DynamoDB `TransactWriteItems`); `S3Store` stays excluded for the same reason it does not implement CAS. `wrap_acl` gains an `_ACLTransactionalMixin` so the BL-156 truthful-isinstance contract extends to the new Protocol. `InMemorySemanticStore` prunes a key's vector on delete or expiry so a query never returns a stale hit; the shipped `Embedder` is a deterministic lexical baseline, not a semantic model (a model-quality embedder satisfies the same Protocol, out-of-tree).
- Key providers (`BL-111`): over a `VersionedKeyProvider`, `EncryptedStore` writes a key-id value envelope so a rotation does not strand prior ciphertext; over a plain `KeyProvider` it keeps the exact prior on-disk format (byte-additive, existing encrypted data unaffected). A KMS-backed provider is out-of-tree (the ADR 0001 stance); the Protocol is the extension point. Adopting a versioned provider on a store sealed by a plain provider works via an authenticated legacy fallback (`BL-181`): a non-envelope value is retried as legacy `nonce+ct` with the current key (AES-GCM auth means no silent wrong value), so the default migration contract is to seed the ring with the existing key as the current version (`LIMITATIONS.md` L16). Opt-in multi-key legacy fallback (`BL-196`, runbook 7.4 #4): pass `legacy_multi_key=True` to `EncryptedStore` / `wrap_encrypted` over a provider that also implements `IterableKeyProvider` (the in-tree `RotatingKeyProvider` does); the legacy fallback then iterates each historical key in the ring, lifting the L16 current-key-only restriction. Default is unchanged so a KMS-backed provider that charges per call is not exposed to extra cost.
- Compaction and tiering scope (`BL-234`, `BL-235`, ADR 0024): `MemoryCompactor(atomic=True)` (the default) requires both `VersionedMemoryStore` and `TransactionalMemoryStore` at construction (so InMemory/SQLite/Redis/DynamoDB qualify; S3 does not) and a concurrent rewrite/expiry/delete of any source between read and commit fails the whole transaction (`compact` returns `None`, store unchanged, the BL-072 give-up convention); `atomic=False` is write-summary-then-delete-sources with a documented single-writer lost-update window, per-source delete-failure containment (the BL-233 idempotent-DELETE convention), and a partial-failure recovery that is lossless only for rolling compaction (`target_key` in `keys`; a non-rolling re-compact rebuilds the summary from survivors alone). One atomic compact on DynamoDB is bounded by the 100-item `TransactWriteItems` cap (99 live sources + the summary write). `TieredMemoryStore` requires the two tiers to agree on namespace `name` and `workload` but they may differ in `retention_seconds` (short-hot/long-cold is the point); it validates keys on its own L1 surface (the `ACLStore` precedent), it deliberately does not forward the inner tiers' extension Protocols (a transaction spanning two tiers has no single-store semantics), a version-gated `demote` that loses its race removes the just-written cold copy again (no stale ghost, no resurrecting a concurrently deleted key), and its `demote_to_capacity` ranking is the wrapper's own first-write order (an overwrite keeps its slot, BL-212; keys the wrapper never wrote carry the BL-224/BL-225 legacy sentinel 0: oldest, demoted first, ties lexicographic; the order map is process-local and resets to the sentinel on restart). The shipped `TruncatingSummarizer` is a byte-budget baseline, not a semantic summarizer (a model-backed `Summarizer` satisfies the same Protocol, out-of-tree).
- Audit base fields: `MemoryAudit` rejects at construction both a partial base-event dict (missing a required key) and one carrying a reserved per-event key (`namespace`, `key`, `principal`, `operation`, ...), so a misconfiguration fails at load, not mid-run.
